# Owner rehearsal on the existing bot

The existing @PROFINO1bot accepts /admintest from the configured owner in their private chat. The command exercises a fixed 1 test USDT reservation and cancellation using a separate database connection.

Set PROFINO_TEST_DATABASE_URL and PROFINO_TEST_DATABASE_NAME through host secrets. The database must have a database-wide catalog setting `profino.environment=isolated-staging` (set only on the independently provisioned test database via ALTER DATABASE), an effective session value that agrees, and a different current_database() name from production. Its name must contain a separate underscore-delimited staging, test, or sandbox segment. Session-only and role-only markers do not qualify. The test DSN must not contain TLS query options; choose `PROFINO_TEST_DB_TLS_MODE=verify-full` with `PROFINO_TEST_DB_TLS_CA_PEM` where needed for verified TLS, or `disable` only on a trusted isolated private network. This policy is independent of the production DSN. These checks supplement, not replace, independent hosting/network and role isolation. Provision the existing synthetic ledger/withdrawal fixtures, an active synthetic owner with the owner's Telegram ID, and at least 1 test USDT. Keep this test owner exclusive to the rehearsal while it runs.

The command reads the production database name to check isolation. Financial operations use the test pool. Repeated processing of the same Telegram message uses the same withdrawal request key. A partial failure can leave a reserved test withdrawal which can be inspected and cancelled in that test database.

This command bypasses the need to enable global isolated-staging simulation mode for the existing bot. The generic staging adapter still retains its separate identity checks. Live investment, blockchain delivery and customer acceptance require separate validation.

The command is implemented on the release candidate. Host configuration, test-data provisioning and a live Telegram run remain outstanding.
